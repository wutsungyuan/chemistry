# 踩過的坑與使用者的意見

## 使用者給過的意見(按時間)
1. 「動畫品質太粗糙」→ 人物保持方塊風,其他物件(圓柱、玻璃杯、燒杯、液體、火焰…)改成圓滑精緻。
2. 手擋臉、滴管像色塊、手臂沒有手肘、氧氣紅色偏淡 → 兩節手臂 + 手肘、滴管重做、重新配置站位與道具高度、氧分子紅色加深。
3. 「揮手只有前臂動、大臂沒動」→ 大臂(肩膀)帶動前臂。
4. 「像皮影戲;前臂早就脫臼了」→ 手肘是單軸鉸鏈,只能彎;揮手由大臂帶動;這是科學類 App 的底線。
5. 「人體動作要符合解剖學還要符合物理學,有人的角色先建骨架人偶再套外皮」→ 骨架優先流程(`rig-spec.md`)。
6. 「物品出場方式不一定要符合物理(影片效果),但出場後跟實驗有關的就要符合科學」→ 兩層規則。(我曾把出場也當成物理限制,是矯枉過正。)
7. 「影片內容跟故事文章要對得起來」→ `exp-scripts.json` 單一資料來源 + `check-sync.mjs`。
8. 中文字幕要有,英文版也要有;長度依語言各算各的。

## 技術教訓
- **色彩**:three r128 沒有自動色彩管理,十六進位顏色要先轉線性(`convertSRGBToLinear`),否則畫面偏白;貼圖要設 sRGB。正式版用 three 0.187.0,改用 `THREE.ColorManagement` 與 `renderer.outputColorSpace`,顏色要重新確認。
- **玻璃**:用「半透明 + 環境反射 + 反光條」,不要用折射。
- **環境反射只給需要的材質**(玻璃、液體、陶瓷、水滴、分子),不要設成整個場景的環境,否則桌子、地板、人物都會偏白。
- **手臂**:一定要兩節 + 手肘鉸鏈;手肘朝外下方彎才不會擋臉;先算手臂可及範圍,不夠就調站位或道具高度。
- **萬向鎖**:肩/髖不要用 Euler 角限制活動範圍;用「仰角 + 運動面 + 軸向旋轉」。
- **比例**:人物、桌子、道具的比例要一起決定;道具太大手就搆不到。
- **重心**:手伸出去要有重心補償(骨盆後移、脊椎前傾),否則像站不穩;前傾上限約 16°,太大像在鞠躬。
- **看向目標**:頭 pitch 要打折,否則低頭看桌上的東西會只看到頭頂。
- **標籤與字幕**:先確認不蓋到人物的臉、不互相重疊、不被截斷;手機上字要夠大。
- **轉場效果**:`pop` 彈出(回彈緩動)給「出場」;不要讓物品憑空消失在實驗過程中。
- **共用的 shader uniform**:多個火焰共用同一個 `uAlpha` 會互相影響(打火機火焰與蠟燭火焰);每個火焰要有自己的亮度與熄滅參數。
- **檢查靠截圖逐格**:比想像可靠;改完要看四個關鍵畫面(開頭、動作最大、結果、結尾),中英文各看一次。
- **工具**:CDP 無頭 Chrome 用 `scripts/lib/cdp.mjs`;`page.eval` 的回傳值若是複雜物件(例如 window)會因序列化失敗,結尾加 `, 0`。

## 資料與流程教訓
- 故事的科學事實與動畫不一致時,**以科學為準,改故事**,並明確告訴使用者(故事是給孩子讀的內容,要請使用者看)。
- 對照表要由資料產生並自動檢查引用,不要手寫。
- 動畫旁白用自己的短句;故事原文太長。
- 英文字幕通常比中文長,動畫長度要各算各的。
- 不要在使用者同意前建立新檔案、提交或推送。

## 這次同時做五個場景學到的
- 引擎要用 `opts.key` 選腳本與字幕(曾經只認 candle 與 cabbage,新場景拿到蠟燭的字幕);E2E 現在每一支動畫都檢查「步驟數與 key 是自己的」。
- 多個代理同時做,要各自只改自己的檔案;共用的 JSON 用 `set-exp.mjs` 一次讀寫;暫存檔要放各自的子資料夾(曾有同名暫存檔互相覆蓋)。
- 開發伺服器的熱更新會讓別人的截圖中途失敗,重跑即可;本機是軟體渲染,每次截圖很慢,`--sweep` 與多張截圖要放背景跑。
- 沒有人物的場景用 `people: false`、沒有桌子的用 `room: false`(夜空、週期表)。
- 大量粒子或分子用 `Points` 或 `InstancedMesh`(繪製呼叫從幾百降到幾十)。
- **尺寸適應(使用者指出)**:不能把畫面比例寫死(曾經固定 16:10、手機再 zoom 1.3,桌機上只是一個窄窄的卡片)。3D 引擎本來就能畫任何尺寸,輸出尺寸與鏡頭構圖都要由容器決定;E2E 的 F2 區檢查桌機、橫式手機、平板的畫面大小與放大模式。
- 畫質自動分級(`quality` 0~2)只降不升;截圖環境是軟體渲染,要用 `--quality 2` 固定,不然會被降級。
- `position:fixed` 在有 transform 的父層裡會被困住,全螢幕要把元素搬到 `<body>`。
