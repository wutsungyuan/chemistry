# 兒童化學樂園 (Kids Chemistry Park)

Three.js 製作的兒童化學學習網站:元素週期表 → 原子 3D → 分子圖鑑 → 分子實驗室(拖拉組合)→ 反應劇場 → 小測驗與徽章。
介面為繁體中文(可開注音)/English。

    npm install
    npm run dev       # 開發(固定 http://127.0.0.1:5174);會先自動建置並驗證結構資料庫
    npm run build     # 輸出到 dist/;會先自動建置並驗證結構資料庫
    npm run build-db  # 只建置並驗證結構資料庫,並檢查所有反應的原子守恆
    npm test          # 單元測試(Node 內建 node:test)

擴充內容:編輯 `src/data/elements.js`(元素與趣味知識)、`src/data/db/`(分子與結構,見下)、`reactions.js`(反應,需原子守恆)。

## 分子/晶體結構資料庫

所有分子的結構(座標與鍵)都放在 `src/data/db/`,**晶體直接放原始 CIF 檔**,不再手抄數字:

| 位置 | 內容 |
|---|---|
| `molecules.json` | 每個分子的名稱、說明、用途、實驗室旗標(不含結構) |
| `structures.json` | 每個分子的結構記錄(依 `kind` 分類,見下) |
| `cif/<COD 編號>.cif` | 來自 Crystallography Open Database(COD)的原始 CIF 檔(44 個:化合物、金屬、岩鹽) |

結構記錄的 `kind`:

- `explicit`:座標直接列出
- `zmat`:用鍵長、鍵角、二面角(Z-matrix)計算座標
- `crystal`:指定一個 CIF(`cif`)與規則,以某個原子為中心長出一小塊晶體(金屬、化合物、合金都用這個)
- `crystalPick`:由 CIF 晶體取出一個小單元(給實驗室任務用,保留原子順序)
- `rocksalt`:CIF 的岩鹽結構,畫成 2×2×2 小立方

### 重用的套件(不重造輪子)

- **three.js**:所有向量、矩陣、角度運算(`Vector3`、`MathUtils`),見 `src/data/geom.js`
- **crystcif-parse**(devDependency,只在建置時用):解析 CIF、套用對稱操作展開晶胞。COD 的 CIF 常缺 `_atom_site_type_symbol` 或寫成 `Sn4+`,載入前由 `scripts/lib/cif.mjs` 補上/正規化
- **node:test**:單元測試(內建,免安裝)

### 流程

`scripts/build-db.mjs`:讀 JSON 與 CIF → `src/data/structureDB.js`、`crystalBuilder.js` 展開 → **驗證** → 寫出 `src/data/generated/db.js`(自動產生,請勿手改,網頁載入時不必再計算)。
`npm run dev` / `npm run build` 會自動先執行;驗證失敗會中止並列出錯誤。

資料出處由 CIF 內容**自動組成**(作者、年份、溫度、COD 編號),圖鑑會顯示。

### 驗證項目

- id 與結構一一對應、每筆都有出處
- CIF:檔案存在、檔內 COD 編號與檔名一致、是室溫(270–320 K)常壓、沒有被遺忘的孤兒 CIF
- 元素存在、鍵與原子索引有效、沒有重複的鍵
- 鍵長合理、沒有鍵連著的原子不能重疊
- 化學式與原子數一致(整個分子類型的記錄)
- 文獻鍵長/鍵角範圍(記錄裡的 `check`):例如剛玉 Al–O 1.80–2.02 Å、金屬最近鄰距離與教科書晶格常數相符
- 實驗室配方的骨架簽章不重複,不會被誤認
- 所有反應原子守恆(`scripts/check-reactions.mjs`,用 `reactions.js` 的 `checkBalance`)

### 單元測試(`npm test`)

`tests/structures.test.mjs`:CIF 前處理與載入、Z-matrix 的鍵長鍵角、岩鹽/方解石/剛玉的配位數與鍵長、金屬(fcc 12 配位、bcc 8 配位)、合金的固定性、小蘇打的原子順序與氫位置、建置腳本整體通過、實驗室配方不重複。

### 新增或修正結構

1. 在 `molecules.json` 加(或改)名稱與說明文字。
2. 晶體:把 COD 的 CIF 放進 `cif/`,在 `structures.json` 加一筆 `kind: "crystal"` 記錄(`cif`、`label`、`rules`、`center`、`depth`、`check`)。其他:加 `explicit` 或 `zmat` 記錄並寫 `source`。
3. 執行 `npm run build-db` 與 `npm test`。

### 資料品質

- 化合物晶體(方解石、剛玉、赤鐵礦、金紅石、石英、膽礬、瀉鹽等)與金屬、岩鹽都來自 COD 的 CIF,並與文獻/教科書鍵長對照。
- 小分子(水、酒精、葡萄糖等)的鍵長鍵角來自常見的實驗/文獻值,尚未逐一對照原始資料庫。
- 次氯酸鈉(NaClO)等找不到可靠結構資料的項目,在圖鑑裡標為「簡化示意」。

## 資訊安全

- **依賴最小化**:執行時依賴只有 `three`、`pinyin-pro`;`crystcif-parse`(連同 `mathjs`、`mendeleev`)只在建置時用,**不會進網頁程式包**(有測試檢查)。
- **鎖定版本**:`package.json` 所有依賴都是確切版本(無 `^`),`package-lock.json` 每個套件都有完整性雜湊且只來自官方 registry。請用 `npm ci` 安裝(依鎖檔還原,不會升級)。
- **不執行安裝腳本**:`.npmrc` 設定 `ignore-scripts=true`。目前只有 `fsevents`(macOS 選用依賴)宣告安裝腳本,已列入白名單,新增任何會跑腳本的套件測試會失敗,需先審查。
- **建置腳本在沙盒內執行**:`npm run build-db` 用 Node 的權限模型(`--permission`)——只能讀專案、只能寫 `src/data/generated/`,不能開子程序、Worker 或原生外掛。第三方 CIF 解析器因此無法做其他事。
- **外部資料不當 HTML**:CIF 來的文字(作者等)顯示前一律經 `escapeHtml`;建置時若出處含 `<` `>` 會失敗。
- **開發伺服器只綁 127.0.0.1**,不對區網開放。
- **新增/升級套件前**:`npm audit`、看套件的安裝腳本與原始碼(有無網路、`child_process`、`eval`),用 `npm i -E` 鎖版本,最後執行 `npm test`(含 `tests/security.test.mjs`)。

## 元素光譜(光譜指紋)

元素頁(週期表 → 點元素)有「🌈 光譜指紋」:原子發光時的彩色亮線(發光光譜),可切換成吸收光譜(彩虹底黑線)。手指點或滑過亮線可看波長與顏色,也有「最亮的幾條線」。手機上在面板頂部分頁(原子資訊 | 光譜);**光譜分頁是一頁、不用捲動的儀表板**:3D 原子、光譜條、電子階梯圖三個圖同時可見(階梯圖會配合剩下的高度),點哪個顏色就立刻看到電子怎麼跳;長篇說明收進「ⓘ」開啟的說明面板(實心背景、蓋住下方面板、有 ✕ 與 Esc 可關閉,不會和圖疊在一起),原子博士提示列、縮放滑桿與「回週期表/念給我聽」在這一頁隱藏。選了顏色後,3D 原子會依畫布大小自動取景(把選取的軌道投影到畫面上的範圍調整鏡頭距離,填滿約 88%)。手機很矮(< 640px)時,階梯圖下方那行說明也先收起來。

- **資料來源**:NIST 原子光譜資料庫(ASD)v5.12,Kramida, Ralchenko, Reader & NIST ASD Team,<https://physics.nist.gov/asd>,DOI 10.18434/T4W30F。畫面上與 `spectra.json` 都有標示出處。
- **只收錄衍生資料**:中性原子在空氣中的可見光(380–780 nm)譜線,每個元素只保留最強的約 40 條(相對強度 0~1),不收錄 NIST 的原始資料。重疊(0.08 nm 內)的精細結構會合併。
- **涵蓋**:118 個元素中 98 個有資料;砈與鐨(Z=100)以後 NIST 沒有可見光譜線,畫面會寫「還沒有量到」。
- **強度**:40 個元素有實驗測得的相對強度;其餘用物理公式估算(發出的能量 ∝ g·A·exp(−Eₖ/kT)/λ),畫面會標「強度是估算的」。溫度 T 由資料決定:用 52 個「同時有實測強度與躍遷機率」的元素,比較估算與實測的順序,6000 K 時斯皮爾曼相關度中位數 0.85(記錄在 `spectra.json` 的 `meta.calibration`)。
- **限制**:螢幕只能近似顯示單色光;亮線畫得比實際粗以便手指點;強度是相對值。

更新資料(需要網路,不屬於 `npm run build`):`node scripts/fetch-spectra.mjs [快取資料夾]`。原始回應只放在快取資料夾(不進專案),每次請求間隔 0.5 秒;之後 `npm run build-db` 會驗證(出處必填、波長在可見光內、依波長排序、最強 = 1、至少 95 個元素有資料、估算相關度 ≥ 0.7)並產生 `src/data/generated/spectra.js`。

### 光譜的延伸功能

- **🪜 電子的樓梯(能階階梯圖)**:選一條亮線,畫出電子從哪一層「樓層」跳到哪一層(發光往下、吸收往上),並有電子跳躍與光子的動畫(尊重「減少動態效果」設定)。能階來自 NIST(eV,已用「能階差 = 光子能量 hc/λ」逐條驗證,誤差 < 2%)。縱軸只畫用到的能量範圍;弱的內層電子線(能階遠高於最亮線)不納入預設的 8 條,避免把真正的亮線壓扁。72% 的譜線有完整能階;15 個元素有光譜但 NIST 沒有能階,就不顯示階梯圖。
- **週期表「🌈 光譜模式」**:每一格換成該元素的迷你光譜條,灰色的是沒有資料的元素。
- **小測驗「光譜偵探」**:看光譜指紋猜元素。題庫是 36 個學過的元素;同一題的選項彼此光譜相似度(10 nm 分格的餘弦相似度)必須 < 0.45,避免鐵、鎳、銅這種肉眼分不出來的組合。答完會顯示最亮線的波長與顏色。
- **徽章**:🌈 彩虹觀察員(看過 5 個元素的光譜)、🕵️ 光譜偵探(答對 3 題光譜題)。
- **中英文一致**:`tests/spectra2.test.mjs` 會檢查中英文文字鍵與 `{變數}` 完全一致。

### 光譜能階與「幾層電子」的關係

- **氫**:只有一顆電子,能階就是它在第 n 層的能量 E = 13.6(1 − 1/n²) eV。巴耳末系(可見光)全部是「跳到第 2 層」。階梯圖的橫槓標 n=2、n=3…(建置時用玻爾公式驗證)。
- **多電子原子**:可見光的躍遷是**最外層(黃球)電子**在跳,內層電子要紫外線/X 光才會動。例如鈉的 D 線是 3s↔3p、鋰的 670.8 nm 是 2s↔2p、鉀的 766.5 nm 是 4s↔4p —— 上下都在同一層,只是子層不同。
- **標籤**:NIST 的組態只有「已填滿的內層 + 恰好一個外層電子」(2p6.3s → 3s)才標,複雜組態(內層被激發、兩顆電子同時在動)不硬標;17 個元素、225 條線有標籤。
- **3D 原子聯動(量子躍遷不是「滑下去」)**:選一條有能階的亮線,上方 3D 原子的最外層電子在上、下兩條虛線軌道上各有一個半透明的**影子**,影子的濃淡 = 在那一層的機率。躍遷時一個影子變淡、另一個變濃,電子**不會經過兩層中間**;發光是「淡出上層 → 淡入下層 → 光子往外飛」,吸收則相反。真實的躍遷只要幾奈秒(鈉的 3p 壽命約 16 奈秒,見 Minev 等人與 arXiv:0802.0779),畫面放慢了約一億倍。階梯圖的動畫用同一份時間軸(`TIMELINE`),測試會檢查兩者一致、狀態裡不能有任何「位置」。軌道半徑只是示意(層數越大越外面、越來越擠;同一層內 s < p < d),真實的電子沒有固定軌道。純函式在 `src/ui/orbitJump.js`。「減少動態效果」時兩層各畫一半濃(=混合),不動。

## 氫的電子雲(第一期)
氫的光譜分頁最前面有「🌫️ 電子雲」按鈕,進入獨立場景(`#cloud/1s`)。只做氫:氫只有一顆電子,薛丁格方程式有精確解,形狀是真的;多電子原子沒有精確解,不做,以免誤導。
- 🌱 國小:「拍照」——每按一次在電子可能出現的地方亮一個點,拍越多雲的形狀越浮現(1s、2s、2p、3d)。
- 🔭 國中:完整的雲 + 名稱 + 能量;預設立體;「✂️ 切開看」只留通過原子核的一薄片(鏡頭正對剖面),才看得到節點(電子絕不出現的地方:2s 的球面、2p 的平面、3d 的兩個圓錐);顏色是波函數的正負。
- 物理在 `src/data/hydrogenOrbital.js`(徑向函數、球諧函數、依 ψ² 精確取樣,不是拒絕取樣的近似);`tests/orbital.test.mjs` 驗證歸一化、平均半徑 ⟨r⟩=(3n²−l(l+1))/2、節點位置、取樣統計,以及 3→2 的光 ≈ 656.3 nm 與光譜資料一致。
- 第二期:「🌊 2p+3d」疊加態——滑桿調混合比例,電子雲沿上下方向來回晃動(干涉項 2ab·ψ₂p·ψ₃d·cos ωt),同時往水平面送出紅色光波圈(強度 ∝ 2ab;純 2p 或純 3d 不晃、不發光)。頻率 = ΔE/h ≈ 4.57×10¹⁴ Hz、波長 656 nm = 氫的 Hα 紅線;畫面放慢約 10¹⁵ 倍。測試用取樣加權驗證 <z>(t) = 2ab·D·cos ωt 與解析的偶極矩陣元一致。
- 第三期:🎓 高中層——量子數與波函數公式 ψ = R(r)·Y(θ,φ)、徑向機率圖 P(r)=r²R²(標出 ⟨r⟩、最可能半徑 r_mp = n²a₀(l=n−1)、徑向節點)、複數軌域 2p₊₁ / 3d₊₂(m≠0:相位 mφ 用色環上色,機率流 J_φ = ħm|ψ|²/(μρ) 以示蹤粒子顯示,L_z = mħ)、疊加態的含時間公式與選擇定則表(偶極矩陣元 D = ∫ψ_A z ψ_B dV:1s↔2p = 0.74、2p↔3d = 2.45 會發光;Δl≠±1 的 D = 0;2s↔2p 的 D = 3 但能量相同所以不晃)。白點是機率流的示蹤粒子,不是電子軌跡;波函數的整體相位不可觀測,所以顏色不動。


## 原子核與同位素、物質的變化
- **原子核與同位素**(`#nucleus/<Z>`):IAEA LiveChart 基態資料(`db/nuclides.json`,出處與擷取日期標在畫面上);半衰期、衰變動畫;三個階段(國小/國中/高中)。
- **物質的變化**(`#matter`,底部導覽「🧊 物質變化」):① 三態與溫度——粒子圖 + 滑桿,國小只有水,國中可選物質並看加熱曲線(變化時溫度停在熔點/沸點的「平台」)與吸熱/放熱,高中加電漿與水的加熱能量;② 物理還是化學變化?的判斷遊戲(37 題,依階段出題,判斷標準是「有沒有產生新物質」)。物質的熔點/沸點(1 大氣壓)已對照 NIST Chemistry WebBook 與 WebElements(出處寫在 `matter.json` 的 meta 與畫面上);水的比熱、熔化熱、汽化熱已對照 CRC 手冊與 NIST 資料(部分經 Wikipedia 轉引);物理/化學變化的 37 題是課本常識,尚未逐題對照原始資料。

## 程式與資料的組織(新增功能時照這個走,不要另起爐灶)
- **資料集**:一個 JSON 放在 `src/data/db/`(含 `meta`:出處、限制、日期)→ 一個驗證模組 `scripts/lib/validate-<名稱>.mjs`(出處必填、範圍、錨點)→ `scripts/build-db.mjs` 呼叫它,並用 `writeModule()` 寫成 `src/data/generated/<名稱>.js`(自動產生,不要手改)→ 純函式放 `src/data/<名稱>.js`(不碰畫面,`tests/` 直接測)。
- **文字**:每個功能一個文字包 `src/i18n/packs/<名稱>.js`(`{ zh, en }` 放同一個檔,不會漏翻),在 `src/i18n/index.js` 的 `PACKS` 登記。`zh.js` / `en.js` 只放共用的基本文字,不要再往裡面堆。
- **共用的小元件**放 `src/ui/`:`level.js`(國小/國中/高中,記住使用者上次選的)、`levelBar.js`(階段選擇鈕)、`particles.js`(粒子示意圖)。第三個地方要用同樣的東西之前,先把它抽到這裡。
- **場景**放 `src/scenes/`,在 `src/main.js` 的 `SCENES` 登記;每個場景要有測試(路由、文字齊全、不理會 prefers-reduced-motion)。
